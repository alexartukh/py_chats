# MyForum — сервер (Django)

Серверная часть SPA-приложения «Комментарии»
форум с темами и древовидными комментариями. Сервер — JSON API на Django и WebSocket (WSGI + ASGI)
для списка пользователей онлайн. Клиент — отдельный проект на React

## Возможности

### Пользователи (users.py)
- Регистрация: логин (только латинские буквы и цифры), e-mail (проверка формата), пароль.
  После регистрации пользователь сразу считается вошедшим — сервер возвращает токен.
- Вход и выход. Авторизация по JWT: токен в заголовке `Authorization: Bearer <token>`.
- Пароли хранятся только в виде хеша (PBKDF2-SHA256). Таблицы в БД для сессий нет.
- Публичная таблица всех пользователей форума.
- Список пользователей онлайн в реальном времени через WebSocket.

### Темы (topics.py)
- Список тем, одна тема, создание темы (только вошедшим).

### Сообщения (messages.py)
- Дерево ответов любой глубины: на любое сообщение можно ответить.
  У каждого сообщения в ответе сервера есть `depth` — глубина в дереве.
- Порядок по умолчанию — LIFO (новые первыми).
- Постраничная выдача: параметры `from` и `to` (номера сообщений, с 1, включительно).
- Отдельный список корневых сообщений темы (для таблицы с сортировкой на клиенте).
- Удаление своего сообщения — вместе со всеми ответами на него. Но только своего.
- Форма сообщения: User Name, E-mail, Home page (необязательно), CAPTCHA, текст, файл.
- Сервер сохраняет IP и User-Agent автора. Но они нигде не используются.

### Разметка текста и защита от XSS
- В тексте разрешены только теги `<a href="" title="">`, `<code>`, `<i>`, `<strong>`.
- Проверяется, что все теги закрыты и правильно вложены; `<a>` внутри `<a>` запрещён.
- Ссылки — только `http://` и `https://` (в том числе Home page), `javascript:` не пройдёт.
- Правила проверки на сервере совпадают с клиентскими (`messageMarkup.js` в клиенте).

### Файлы к сообщению
- Картинки JPG, GIF, PNG и текстовые файлы TXT.
- Картинка больше 320×240 уменьшается пропорционально. Маленькие картинки не меняются.
- TXT — не больше 100 КБ.
- Тип картинки проверяется по содержимому (первым байтам), а не только по расширению.

### CAPTCHA
- Картинка PNG со случайным 3-значным числом, рисуется на сервере. Для капч есть отдельная таблица в БД.
- Одноразовая: проверяется только один раз (верно или нет — запись удаляется), живёт 5 минут.
- Обязательна при отправке сообщения.

### Безопасность
- Защита от SQL-инъекций — все запросы через Django ORM.
- Защита от XSS — см. «Разметка текста» выше.
- Проверка всех входных данных на сервере (типы, длины, форматы) с понятными текстами ошибок.
- Секреты и настройки — в `.env`, не в коде.
- CORS разрешён для клиента; `ALLOWED_HOSTS` проверяется.

## Структура проекта

```
app.py                  настройки Django, маршруты HTTP и WebSocket, запуск
orm.py                  модели Django ORM (users, topics, messages, captchas)
auth.py                 TokenService: создание и проверка JWT
password_helper.py      хеширование и проверка паролей
request_check_helper.py проверки входных данных запроса (JSON, поля, токен, IP, User-Agent, разметка). Сделан для разгрузки классов в папке views.
messages_helper.py      файлы к сообщениям, уменьшение картинок, пейджер, дерево сообщений
CAPTCHA.py              выдача и проверка CAPTCHA
online.py               WebSocket: список пользователей онлайн
views/users.py          UsersApi    — пользователи, регистрация, вход, выход
views/topics.py         TopicsApi   — темы
views/messages.py       MessagesApi — сообщения
init.sql                схема БД PostgreSQL + тестовые пользователи и темы
init_messages.sql       тестовые сообщения (по 10 корневых и 40 ответов в каждой теме)
schema_mysql.sql        та же схема на диалекте MySQL — для MySQL Workbench
.env.example            образец файла настроек
```

Таблицы создаются скриптом `init.sql`, а не миграциями Django: у моделей `managed = False`.

## API

Все ответы — JSON. Ошибки: `{"error": "текст"}` с кодом 400, 401, 403, 404, 405 или 409.
Защищённые адреса требуют заголовок `Authorization: Bearer <token>`.

| Метод | Адрес | Доступ | Что делает |
|---|---|---|---|
| GET | `/api/users` | все | список пользователей |
| POST | `/api/create_new_user` | все | регистрация → `{token, login, email}` |
| POST | `/api/login` | все | вход → `{token, login, email}` |
| POST | `/api/logout` | все | выход (токен удаляет клиент) |
| GET | `/api/topics` | все | список тем |
| GET | `/api/topic?topic_id=1` | все | одна тема |
| POST | `/api/create_new_topic` | токен | создать тему |
| GET | `/api/messages?topic_id=1[&from=1&to=25]` | все | сообщения темы деревом, с `depth` |
| GET | `/api/get_all_root_messages?topic_id=1` | все | только корневые сообщения темы |
| POST | `/api/create_new_message` | токен + CAPTCHA | создать сообщение или ответ |
| POST | `/api/delete_existing_message` | токен, автор | удалить сообщение с ответами |
| GET | `/api/captcha` | все | `{captcha_id, image}`, image — PNG в base64 |
| WS | `/ws/online?token=…` | токен | сервер присылает `{"type": "online_users", "users": [...]}` |

## Запуск с нуля

Нужны: Python 3.14+, PostgreSQL 15+, Redis 5+.

1. **Зависимости:**
   ```
   pip install -r requirements.txt
   ```
   На Windows с Python 3.15 пакет `autobahn` (зависимость `daphne`) может не собраться без компилятора.
   Тогда: `set AUTOBAHN_USE_NVX=0` (PowerShell: `$env:AUTOBAHN_USE_NVX="0"`) и повторить установку.

2. **Настройки:** скопировать `.env.example` в `.env` и заполнить. Описание каждой переменной — в самом файле.

3. **База данных:**
   ```
   createdb -O <пользователь> tops
   psql -h localhost -U <пользователь> -d tops -f init.sql
   psql -h localhost -U <пользователь> -d tops -f init_messages.sql
   ```
   `init_messages.sql` можно выполнить только один раз на базу.

4. **Запуск:**
   ```
   python app.py runserver
   ```
   Сервер: `http://127.0.0.1:8000`. Команда запускает ASGI-сервер Daphne — он обслуживает и HTTP, и WebSocket.

5. **Клиент** — отдельный проект (React + Vite), запускается отдельно.

## Запуск в Docker

Образ содержит только сервер. PostgreSQL и Redis должны работать отдельно (локально, на виртуалке
или у хостинга); их адреса задаются в `DATABASE_URL` и `REDIS_URL`. База должна быть уже создана
скриптами `init.sql` и `init_messages.sql` (см. «Запуск с нуля», шаг 3).

1. **Сборка образа** (из корня проекта):
   ```
   docker build -t myforum-server .
   ```

2. **Запуск:**
   ```
   docker run --rm -p 8000:8000 --env-file .env myforum-server
   ```
   - `--env-file .env` — переменные берутся из `.env` на вашей машине. В образ `.env` не попадает (`.dockerignore`).
   - `-p 8000:8000` — порт 8000 компьютера ведёт на порт 8000 контейнера.
   - `--rm` — контейнер удаляется после остановки.

   Сервер: `http://127.0.0.1:8000`, WebSocket: `ws://127.0.0.1:8000/ws/online?token=…`.

3. **Остановка:** `Ctrl+C` в том же окне или `docker stop <id>` (`docker ps` покажет id).

**Что учесть:**
- Внутри контейнера `localhost` — это сам контейнер, а не ваш компьютер. Если PostgreSQL или Redis
  запущены прямо на компьютере, в `.env` вместо `localhost` укажите `host.docker.internal`.
  Адреса виртуалки (например, `192.168.33.10`) работают без изменений.
- Порт можно сменить переменной `PORT` (так делает, например, Render): `-e PORT=9000 -p 9000:9000`.
- Сервер запускается командой `python app.py runserver` — с `daphne` в `INSTALLED_APPS` это ASGI-сервер Daphne,
  а не сервер разработки Django. Автоперезапуск выключен (`--noreload`).

## Схема БД в MySQL Workbench

`File → Import → Reverse Engineer MySQL Create Script…` → `schema_mysql.sql` → `Execute`,
затем `Model → Create Diagram from Catalog Objects`. Соответствие типов PostgreSQL и MySQL — в шапке `schema_mysql.sql`.
